## Deploy (kullanici yapar)
1. `supabase login`, `SUPABASE_DB_PASSWORD="$(cat ~/.supabase/zerospike.dbpass)" supabase link --project-ref jcpepqectdubbmchhdsn`.
2. Migration: `SUPABASE_DB_PASSWORD="$(cat ~/.supabase/zerospike.dbpass)" supabase db push`. Cron isleri migration ile gelir: purge-app-events 03:17, purge-spike-logs 03:17, purge-subscription-events 03:27, purge-feedback 03:37 (UTC).
3. Fonksiyonlar: `supabase functions deploy <ad> --project-ref jcpepqectdubbmchhdsn --use-api` (track, rc-webhook, delete-device, ai-ask-spike, feedback). `functions/_shared/event-schema.json` degisince track yeniden deploy edilmeli: sunucu once, uygulama surumu sonra.
4. Duman testi: /track 202, /rc-webhook yanlis sirla 401 dogru sirla 200, /delete-device 200, /ai-ask-spike 200.
5. SIRA ONEMLI: once yeni projede ai-ask-spike, track, delete-device deploy (adim 3), sonra eski projedeki 4 yonlendirici. Eski projeye yonlendirici deploy (eski hesaba `supabase login`): `supabase functions deploy <ad> --project-ref zobtmenqgsradocrxdtc --workdir supabase/legacy-forwarders --use-api` (repo kokunden).
6. Eski projede yonlendiricilerce kullanilmayan sirlari sil (eski hesapta): `supabase secrets unset AWS_BEARER_TOKEN_BEDROCK RC_WEBHOOK_SECRET SPIKE_MODEL SPIKE_MODEL_PREFIX AWS_REGION --project-ref zobtmenqgsradocrxdtc`. Bedrock token'i yenilendiyse eskisini AWS'den iptal et.

## Geri bildirim (feedback)
Fonksiyon `feedback` (POST JSON, verify_jwt kapali, CORS yok). Kurulum kimligi `x-device-id` basligi veya govdede `install_id` (baslik oncelikli), kucuk harfli uuid; gercek IP `resolveCallerIp`. Govde: `kind` (suggestion, bug, other, cancel_survey), `reason_code` (yalniz cancel_survey: expensive, not_used, missing_feature, bug, other_app, other), `message` (en cok 2000 karakter, kontrol karakterleri atilir, fazlasi kirpilir), `contact_email` (yalniz kullanici yazarsa, en cok 254), `app_version`, `platform` (ios, android), `locale`. suggestion, bug ve other icin mesaj zorunlu; cancel_survey icin kod veya mesajdan biri yeter. Yanitlar: 200 {ok:true}, 400 (bad_device_id, bad_request, bad_kind, bad_reason_code, bad_message, empty_feedback, bad_contact_email, bad_platform), 405, 413 (32 KB ustu), 429 + Retry-After, 500 not_configured, 503 storage. Fonksiyon hicbir sey loglamaz.

Tablo `public.feedback` (RLS acik, politika yok, yalniz service role): id, created_at, install_id, kind, reason_code, message, contact_email, app_version, platform, locale. Saklama 180 gun: `purge_feedback(180)`, cron `purge-feedback` 03:37 UTC. Oran siniri `feedback_usage` sayaclariyla (anahtarli gunluk hash, ham IP ve kurulum kimligi tutulmaz): IP basina 30/saat, kurulum basina 5/saat; `feedback_submit()` sayim ve eklemeyi tek islemde yapar. Silme kapsami: `delete_device_data_v2` o kurulum kimligine ait feedback satirlarini siler ve sonucta `feedback` sayisini doner. Test: `supabase/tests/feedback.sql` (BEGIN/ROLLBACK), `deno test --allow-env --allow-net supabase/functions/feedback`. Deploy sirasi: migration (`20261020120000_feedback.sql`) once, fonksiyon sonra.

## Bilinen kisit
Yonlendiriciler gercek istemci IP'sini X-Zs-Client-Ip ve X-Zs-Forwarder (FORWARDER_SECRET) basliklariyla iletir (Supabase gateway'i X-Forwarded-For'u yeniden yazar, o yuzden XFF kullanilmaz); yeni proje IP'yi yalniz sir birebir eslesirse kullanir (`resolveCallerIp`, `functions/_shared/http.ts`), aksi halde baglanti IP'sine duser. Gelen X-Zs-Forwarder ve X-Zs-Client-Ip yonlendiriciden gecmez. FORWARDER_SECRET iki projede de ayni degerle ayarlanmazsa eski surum trafigi yine tek IP gorunur ve per-IP tavanlar (track 600/saat, ai-ask-spike 60/saat, delete-device 30/saat) onlari birlikte sinirlar. Izle: v_event_daily ve track 429 orani. Eski proje kapaninca yeni projede `supabase secrets unset FORWARDER_SECRET --project-ref jcpepqectdubbmchhdsn`. Deploy sonrasi dogrulama: eski URL'ye farkli aglardan istek at, sonra `supabase db query --linked "select count(distinct ip_hash) from public.spike_ip_usage where hour_start > now() - interval '1 hour'"` farkli ip_hash sayisini vermeli (tek deger gorunuyorsa sir eslesmiyor). 2026-10-18'de canli dogrulandi: yonlendiricili cagri, ayni makineden dogrudan cagriyla ayni ip_hash kovasina yazildi.
